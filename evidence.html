Tested code · synthetic data · held-out years

We trained a model and tested it on years it never saw

The code is public. It generates made-up utility data for 5,000 assets over 8 years (40,000 asset-years), trains on 2019 to 2024, and tests on 2025 and 2026. Everything below comes from running that code. Because we wrote the data generator, these numbers show the pipeline works. They do not show how real equipment behaves.

30,000 / 10,000Training rows and held-out test rows. The test years come after the training years, so the model cannot peek.
0.75Model AUC on held-out years, against 0.72 for a plain "older means riskier" rule. 0.5 is a coin flip.
80% → 90%Share of real failures that had a spare in the same region, when the same spares are placed by predicted risk instead of by asset count.

Read this before quoting a number.
  • 461 failures in the test years. Enough for a rough read, not for fine claims.
  • The boosted model ranks assets better (AUC, precision) but its Brier error is no better than the age-only rule, so its risk numbers are not better calibrated.
  • Regions differ in age and storm exposure by design in our generator, so a risk-based policy is bound to help. A real utility may or may not look like this.
  • This is one run of one made-up world. A real pilot would use the client's records.
  • The Live model page runs the same trained model in your browser. Its results match the Python results to about 7 decimal places.

Run it yourself

The code, data files and 6 tests are in the Asset-readiness repository on GitHub. Install the requirements, run python run_all.py, then python -m pytest.
